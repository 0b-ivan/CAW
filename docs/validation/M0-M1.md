## Entscheidungen und Grenzen

- Die reinen SdPack-/Katalog-/History-Algorithmen bleiben erhalten, weil sie
  keine X4-Hardware aufrufen. Kein Import-Kommando, keine Dateisnapshots,
  keine Arduino-/E-Ink-/HalStorage-Abhängigkeit und kein Demo-Spieldeck.
- Der Host ist eine Rolle unabhängig von den Sitzen. Host-Token-Prüfung,
  WebSocket-Bindung, echte Resume-Sockets und Persistenz-Thread gehören M2.
- Snapshots speichern Restzeit und rebasiertes Offline-Alter; der Spieltisch
  steht während eines Neustarts still. Deck und Blocker werden lokal
  bereitgestellt. Snapshots enthalten private Daten und sind keine Frames.
- Die originale Formatierung der übernommenen Header und Tests bleibt
  absichtlich bestehen; Formatter prüft eigenen Code im Google-Stil.
- TLS terminiert bei Caddy. uSockets wird ohne eigenen TLS-Stack gebaut;
  unnötige rekursive TLS-/QUIC-Submodule werden nicht geladen.
- Redis-plus-plus 1.3.13 benötigt im FetchContent-Build die öffentliche
  Weitergabe seines generierten Hiredis-Headers. Seine alte CMake-
  Policy-Baseline wird nur während dieses Subprojekts von der
  Deprecation-Meldung ausgenommen; Compiler-Warnungen bleiben Fehler.
- Echte Domain/TLS, Spiel-Lasttests, Neustartwiederherstellung aus Redis und
  öffentlicher Produktivbetrieb wurden nicht als M0/M1-Leistung getestet.
